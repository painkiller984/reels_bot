# Reels Bot

Telegram-бот для управляемого производства коротких AI-видео: от брифа и сценария до рендера, проверки качества и публикации.

Рабочий облачный вертикальный срез: Telegram-мастер принимает бриф и обязательное изображение продукта, OpenRouter анализирует изображение и пишет сценарий, HeyGen создаёт или анимирует аватара, озвучивает текст и подбирает фоновую музыку, FFmpeg монтирует вертикальный MP4 с продуктом, переходом и субтитрами, ffprobe выполняет техническую проверку. Готовый ролик автоматически отправляется пользователю. Состояние задач хранится в PostgreSQL.

## Быстрый старт

```bash
npm install
npm test
npm run demo
```

Локальная техническая проверка FFmpeg и ffprobe:

```bash
npm run demo:local
```

Без `DATABASE_URL` бот автоматически использует постоянное файловое хранилище `.data/jobs.json`. Для PostgreSQL укажите URL и примените миграцию:

```bash
npm run db:deploy
npm start
```

Для запуска Telegram-бота скопируйте `.env.example` в `.env`, добавьте токен от BotFather и выполните:

```bash
npm start
```

Альтернативный запуск в контейнере после установки Docker:

```bash
docker compose up --build
```

## Команды

- `/create` — пошаговый мастер полного брифа;
- `/create тема` — быстрый старт мастера с готовой темой;
- `/status ID` — показать статус;
- `/queue` — последние задачи;
- `/preview ID` — отправить готовый MP4 в Telegram;
- `/connect_youtube` — подключить YouTube-канал владельца через Google OAuth;
- `/publish ID` — опубликовать готовый ролик;
- `/retry ID` — повторить упавшее производство;
- `/cancel ID` — безопасно отменить ожидающую задачу;
- `/health` — показать состояние провайдеров;
- `/settings` — показать активные режимы.

## Архитектурные правила

- Статусы меняются только через конечный автомат `src/domain/workflow.ts`.
- Внешние сервисы подключаются через порты `src/application/ports.ts`.
- LLM не управляет очередями, ретраями и публикацией.
- Результаты этапов являются версионируемыми артефактами.
- Публикация хранит независимый результат для каждой платформы.

## Производственный media-режим

При `MEDIA_MODE=local` FFmpeg выполняется внутри контейнера на сервере — это не означает запуск на компьютере пользователя. Бот создаёт вертикальный MP4, размещает изображение продукта, прожигает субтитры и проверяет видео, аудио, ориентацию и длительность через ffprobe. `MEDIA_MODE=mock` предназначен только для тестов.

При `TTS_PROVIDER=heygen` HeyGen выполняет TTS и синхронизацию губ. Аватар создаётся автоматически по контексту аудитории, по пользовательскому описанию или из загруженной фотографии человека.

## Проверяемая конфигурация YouTube

Заполните `.env` значениями OAuth-клиента Google и сохраните `YOUTUBE_PRIVACY_STATUS=private`. После запуска бота выполните `/connect_youtube` на том же компьютере, где запущен процесс, затем подтвердите доступ к тестовому каналу. Команда `/publish ID` загрузит готовый MP4 через YouTube Data API и вернёт настоящую ссылку на ролик.

Для теста OAuth-экран должен быть в режиме **Testing**, а ваш Google-аккаунт добавлен в **Test users**. Авторизация и токены хранятся локально в `.data/youtube-tokens.json`, поэтому этот файл нельзя передавать работодателю или добавлять в репозиторий.

## Генерация сценария

`SCRIPT_PROVIDER=openrouter` использует OpenRouter. Модель задаётся через `OPENROUTER_MODEL`; изображение продукта отправляется модели как визуальный контекст. Для демонстрации используется `openrouter/free`.

## Восстановление

При запуске бот возвращает незавершённое производство в очередь с начала безопасной последовательности. Прерванная публикация автоматически не повторяется: задача переводится в ошибку, чтобы повторный запрос не создал дубликат на социальной платформе.

## Облачное развёртывание

`render.yaml` создаёт Docker Web Service и PostgreSQL в регионе Frankfurt. В Render необходимо вручную заполнить секреты `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY` и `HEYGEN_API_KEY`. Контейнер применяет миграции перед запуском и предоставляет `/health`. На Render бот автоматически использует Telegram webhook из `RENDER_EXTERNAL_URL`; локально используется long polling.

YouTube, Instagram и TikTok намеренно не входят в текущий этап. Публикация подключается после проверки полного производственного пути до готового MP4.
