# Reels Bot

Telegram-бот для управляемого производства коротких AI-видео: от брифа и сценария до рендера, проверки качества и публикации.

Облачный production-конвейер: Telegram-мастер принимает бриф и от одного до шести изображений продукта, Gemini или OpenRouter анализирует материалы и пишет сценарий, HeyGen создаёт или анимирует аватара и озвучивает текст, FFmpeg строит динамический вертикальный монтаж с полноэкранными product-сценами, сменой планов, карточками, музыкой и субтитрами. ffprobe выполняет техническую проверку. Готовый ролик автоматически отправляется пользователю. Состояние задач хранится в PostgreSQL, а медиа каждого завершённого этапа — в закрытом Cloudflare R2.

## Быстрый старт

```bash
npm install
npm test
npm run demo
```

Локальная техническая проверка FFmpeg и ffprobe:

```bash
npm run demo:local
```

Без `DATABASE_URL` бот автоматически использует постоянное файловое хранилище `.data/jobs.json`. Для PostgreSQL укажите URL и примените миграцию:

```bash
npm run db:deploy
npm start
```

Для запуска Telegram-бота скопируйте `.env.example` в `.env`, добавьте токен от BotFather и выполните:

```bash
npm start
```

Альтернативный запуск в контейнере после установки Docker:

```bash
docker compose up --build
```

## Команды

- `/create` — пошаговый мастер полного брифа;
- `/create тема` — быстрый старт мастера с готовой темой;
- `/done` — закончить загрузку изображений продукта;
- `/status ID` — показать статус;
- `/queue` — последние задачи;
- `/preview ID` — отправить готовый MP4 в Telegram;
- `/connect_youtube` — подключить YouTube-канал владельца через Google OAuth;
- `/publish ID` — опубликовать готовый ролик;
- `/retry ID` — повторить упавшее производство;
- `/cancel ID` — безопасно отменить ожидающую задачу;
- `/health` — показать состояние провайдеров;
- `/settings` — показать активные режимы.

## Архитектурные правила

- Статусы меняются только через конечный автомат `src/domain/workflow.ts`.
- Внешние сервисы подключаются через порты `src/application/ports.ts`.
- LLM не управляет очередями, ретраями и публикацией.
- Результаты этапов являются версионируемыми артефактами.
- Публикация хранит независимый результат для каждой платформы.

## Производственный media-режим

При `MEDIA_MODE=local` переносимые FFmpeg и ffprobe выполняются на сервере — это не означает запуск на компьютере пользователя. Бот создаёт вертикальный MP4 и использует каждое настоящее изображение продукта в нескольких композициях: полноэкранный hero-кадр с плавным приближением, карточка рядом с аватаром, смена изображения в середине и товарный акцент под CTA. При нескольких фотографиях они автоматически распределяются по сценам. `MEDIA_MODE=mock` предназначен только для тестов.

AI Director вместе со сценарием формирует безопасный монтажный план: 4–7 сцен, тип композиции, длительность, движение, переход, стиль субтитров и настроение музыки. FFmpeg исполняет только разрешённый набор эффектов — LLM не может подставить произвольную команду. В production невалидный или слишком короткий сценарий повторно запрашивается у LLM и при повторной неудаче останавливается до платного HeyGen. Динамический монтажный шаблон используется только как безопасная форма режиссёрского плана, но не подменяет содержание сценария.

`BROLL_PROVIDER=openrouter` разрешает AI Director запросить до `OPENROUTER_BROLL_COUNT` дополнительных вертикальных фонов через `OPENROUTER_IMAGE_MODEL`. Генерация вызывается только для реально используемых сцен и дополнительно ограничена `OPENROUTER_BROLL_MAX_COST_USD`. Реальный товар или скриншот не отправляется генератору на перерисовку: исходные пиксели накладываются поверх фона. Модель получает запрет на упаковку, логотипы, надписи, устройства, интерфейс и вымышленные характеристики. Для полного режима по умолчанию используется дешёвая `google/gemini-3.1-flash-lite-image` (Nano Banana 2 Lite), максимум два фона.

При `TTS_PROVIDER=heygen` HeyGen выполняет TTS и синхронизацию губ. Для экономного режима задайте `HEYGEN_DEFAULT_AVATAR_ID`: этот готовый аватар переиспользуется без повторной платы за создание. Новый аватар создаётся только после явного выбора описания внешности или загрузки фотографии. `HEYGEN_MAX_ESTIMATED_JOB_COST_USD` блокирует задачу до обращения к API, если ориентировочная стоимость превышает установленный предел.

Бот запрашивает у HeyGen sidecar SRT и использует реальные таймкоды речи. Если провайдер не вернул SRT, включается локальный резервный расчёт. FFmpeg ограничивает субтитры двумя строками, нормализует голос, добавляет тихую музыку и завершает композицию строго по длительности основного видео. Проверка качества контролирует кодеки, FPS, длительность, таймкоды и длину субтитров, среднюю громкость, финальную тишину и продолжительность чёрных кадров.

## Постоянное хранение медиа

Для облачного режима установите `OBJECT_STORAGE=r2` и заполните `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`. Аудио, аватар, итоговый MP4 и отчёт загружаются в закрытый bucket сразу после каждого завершённого этапа. Поэтому перезапуск продолжает задачу с последнего сохранённого результата и не повторяет дорогой HeyGen без необходимости. `/preview` и `/publish` автоматически восстанавливают локальную копию из R2, а `/status` выдаёт временную ссылку на один час. Без R2 используется временная папка сервера.

## Проверяемая конфигурация YouTube

Заполните `.env` значениями OAuth-клиента Google и сохраните `YOUTUBE_PRIVACY_STATUS=private`. После запуска выполните `/connect_youtube` в Telegram и подтвердите доступ к тестовому каналу в браузере. Токены сохраняются в PostgreSQL. Команда `/publish ID` загрузит готовый MP4 через YouTube Data API и вернёт настоящую ссылку на ролик.

Для теста OAuth-экран должен быть в режиме **Testing**, а ваш Google-аккаунт добавлен в **Test users**. При PostgreSQL OAuth-токены хранятся в базе; файловый режим использует `.data/youtube-tokens.json`. Этот файл нельзя передавать работодателю или добавлять в репозиторий.

## Генерация сценария

`SCRIPT_PROVIDER=gemini` использует прямой Gemini API. Для высоких бесплатных лимитов и анализа нескольких изображений рекомендуется стабильная мультимодальная модель `GEMINI_MODEL=gemini-3.5-flash-lite`. Требуется `GEMINI_API_KEY` из Google AI Studio.

`SCRIPT_PROVIDER=openrouter` использует OpenRouter. Модель задаётся через `OPENROUTER_MODEL`; изображения продукта отправляются модели как визуальный контекст. Рабочая конфигурация использует `google/gemini-3.5-flash-lite`: она возвращает сценарий и монтажный план по строгой JSON Schema. В production при недоступности API или нарушении длительности задача завершается понятной ошибкой до обращения к HeyGen; шаблонная смысловая подмена запрещена.

## Восстановление

При запуске бот возвращает незавершённое производство в очередь и продолжает с последнего сохранённого артефакта в R2. Прерванная публикация автоматически не повторяется: задача переводится в ошибку, чтобы повторный запрос не создал дубликат на социальной платформе. После публикации `/status` обновляет просмотры, лайки и комментарии через YouTube Data API.

## Облачное развёртывание

`render.yaml` создаёт Node Web Service и PostgreSQL в регионе Frankfurt. В Render необходимо заполнить секреты `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY`, `HEYGEN_API_KEY`, `R2_ACCESS_KEY_ID` и `R2_SECRET_ACCESS_KEY`; также задаются `R2_ACCOUNT_ID` и имя bucket. Сервис применяет миграции перед запуском и предоставляет `/health`. На Render бот автоматически использует Telegram webhook из `RENDER_EXTERNAL_URL`; локально используется long polling.

YouTube подключён через OAuth; Instagram и TikTok пока намеренно не входят в текущий этап.
